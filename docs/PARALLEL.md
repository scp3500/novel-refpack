# 并行执行与调度指南

本项目通过解耦长文本处理流程，将全书拆分为互不依赖的独立任务单元。各任务具备确定性的输入输出路径与独立上下文，支持高并发调度与断点续跑。

---

## 1. 架构原则

1. **无状态与零依赖**：同阶段的子任务互不读取彼此的中间状态，仅消费前置产物。
2. **确定性落盘**：每个子任务对应唯一的输入文件与输出文件，执行结果直接写入磁盘，避免进程间内存共享。
3. **天然故障隔离**：单分片处理失败不影响其他任务，失败任务直接重跑对应编号即可补齐。
4. **幂等断点续跑**：调度器检测到目标产物已存在且大小合规时会自动跳过，中断后执行相同命令即可继续。

---

## 2. 各阶段并发与粒度参考

| 流水线阶段 | 任务拆分粒度 | 单任务输入规模 | 产物规模 | 推荐并发 |
|---|---|---|---|---|
| `02_run_notes.py` (一层摘要) | 单个文本分片（片数 = 总字数 / 60k） | 约 5-6 万字 (≈30k-40k token) | 1,500-3,000 字 | 16 - 64 路 |
| `05_run_volumes.py` (二层卷纪要) | 单卷（以章节/卷为单位） | 卷内分片摘要合集 (≈4k-6k token) | 3,000-5,000 字 | 16 - 32 路 |
| `05_run_volumes.py --meta` (元章节) | 全局元设定（固定 6 项） | 卷纪要提炼素材 (≤6 万字) | 1,000-4,000 字 | 6 路 |
| `06` - `11` (文风索引与成品生成) | 全书级别集中计算 | 语料与统计缓存 | - | 单进程本地计算 |

> **说明**：二层卷纪要直接消费一层产出的结构化摘要，无需重新读取单卷的原始长文本，以控制上下文开销并提升吞吐效率。

## 3. 执行模式

### 模式 0：当前交互式 Agent 调度（首选推荐，零配置）

如果你正在一个交互式 Coding Agent（如 Pi、Claude Code 等）环境中，**强烈推荐首选此方式**：
- **完全免配置**：不需要配置 `config/project.json` 的 API Key、中转地址或后端模式，直接复用当前会话已绑定的模型与执行权限；
- **原生多子代理调度**：由主 Agent 直接调用环境自带的子代理编排工具（如 `subagent`）并行派发任务，每个子代理独立读取 `chunk_NN.txt`，按照提示词模板直接写出 `work/notes/chunk_NN.md`；
- **一体化全自动**：切片、派工、汇总、元章节、提取、生成全部由当前 Agent 一体化完成，人类仅需在对话窗口发起一次需求。

---

### 模式 A：API 线程池调用（备选）

适用于调用云端模型 API 或本地兼容接口（如 vLLM / Ollama）。系统在进程内维护线程池，支持自动重试与指数退避：

```bash
# 启动 32 路并发摘要
python scripts/02_run_notes.py --par 32

# 指定编号单跑或补跑
python scripts/02_run_notes.py --only 3,7,12
```

运行日志按分片记录于 `work/logs/notes/chunk_NN.log`，方便单独排查网络超时与接口报错。

### 模式 B：子代理 / CLI 命令模式

适用于通过独立的命令行 Agent 工具（如无会话的 CLI 执行器）拉起子进程：

在 `config/project.json` 中配置后端命令：

```jsonc
"llm": {
  "backend": "command",
  "command": "my-agent -p --no-session --tools read,write < {prompt_file} > {out_file}",
  "concurrency": 32,
  "timeout": 1800,
  "retries": 3
}
```

- **任务隔离**：通过进程级别隔离运行环境，单任务的临时状态随子进程退出自动清理。
- **权限收敛**：建议限制子代理仅开放基本的文件读写能力，关闭网络与多任务探索权限。

## 4. 容量估算与流控

### 排空耗时计算

$$\text{总排空时间} \approx \frac{\text{子任务总数}}{\text{并发路数}} \times \text{单任务平均执行耗时}$$

- 单分片（约 5 万字）输入生成 2,000 字摘要时，主流推理服务的平均耗时约为 30 - 90 秒。
- 示例：80 个分片在 40 路并发下，通常在 2 - 3 轮并发调度（约 2 - 4 分钟）内完成排空。

### 限流策略与压测建议

1. **预热验证**：初次配置或更换模型后端时，先采用小并发验证单片输入输出连通性：
   ```bash
   python scripts/02_run_notes.py --only 1,2 --par 2
   ```
2. **限流退避**：当并发数触碰 API 服务商的 RPM / TPM 上限时，底层驱动会依据 `retries` 配置自动等待重试。若重试频繁，应下调 `--par` 参数。

---

## 5. 并行作业规范

为确保多路并发产物可直接用于下游自动合并，执行过程应遵循以下要求：

1. **独立输入边界**：单任务仅处理其分派的分片文本，避免跨片引用未授权内容。
2. **严格遵循模板契约**：提示词模版中的字段名与层级标题必须固定，防止多路输出格式漂移导致下游合并脚本解析失败。
3. **跨片逻辑统一收口**：全局世界观、长线伏笔与时间线对齐等跨分片信息，交由 Stage 5（二层卷纪要与元章节）统一处理，不在分片一层阶段做推测。

---

## 6. 断点补跑与产物校验

流水线各阶段支持随时中断与增量续跑：

```bash
# 中断后继续执行：已成功生成的有效分片会自动跳过，仅处理缺失分片
python scripts/02_run_notes.py

# 校验一层产物完整度与片尾覆盖率
python scripts/03_merge_notes.py --check
```

`03_merge_notes.py` 会抽取每片末尾的特征词校验摘要内容。若模型在长文本输入中发生跳读导致片尾信息丢失，校验器将输出警告提示针对对应分片重新生成。
