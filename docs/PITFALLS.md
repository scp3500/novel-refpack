# 指标目标、双轨验收标准与常见问题排查

本文档归纳流水线各阶段的量化验收标准（严格区分**同题材续写**与**跨题材纯文风仿写**）、第 0 层卫生机制、执行中可能遭遇的工程异常及统计维度的有效性边界。

---

## 1. 双轨文风验收标准（`scripts/11_verify.py`）

不同创作目标适用不同的核心判据，切忌用同题材的字词硬门槛去错杀跨题材原创稿件：

| 验收维度 | 轨道 A · 同题材续写 / IF 线（默认） | 轨道 B · 跨题材纯文风仿写（`--cross-domain` + `--domain-terms`） |
|---|---|---|
| **第 0 层 · 卫生层（硬门槛）** | **必须全部清零**：乱码/非目标文字 `0`、零频词 `0`、低频错配搭配替换、语料拟合 AI 探针清零、**照抄例句粘贴 == `0`** | **同样必须全部清零**：乱码 `0`、语域串台零频词/低频搭配替换、语料拟合 AI 探针清零、**照抄例句粘贴 == `0`** |
| **第 1 层 · 门槛层（含 `--pov` 分桶）** | 句长、对白占比、段长、每千字标点密度落在同类场景/同视点参考区间内 | **核心权重之一**：标点密度（逗号/句号/破折号/省略号/问叹号）与句段节奏贴合目标书同视点（`--pov`）区间 |
| **第 2 层 · 结构与虚词骨架层** | 相邻段实词重合自打乱比值接近同类语料中位数 | **核心权重之一**：**虚词骨架相似度**（连接词、副词、助词、代词分布）与句法骨架贴合目标书，不强求实词重合 |
| **第 3 层 · 逐句 `z` 分数（`--top-z`）** | 台词与叙述 4-gram 条件归一化 `z` 均值均落在 **`±0.3`** 区间 | 传入 `--domain-terms` 屏蔽新题材合理专词后，重点看**掩码后 `z`** 是否收敛，并逐句清查 Top-N 高 `z` 句中的语域串台俗词 |
| **第 4 层 · 0 频探针倍数** | 新造 4-gram 比率相对原作基准 **`≤ 1.05x`**（超过 `1.30x` 必须返工） | 仅作诊断参考（新题材词天然抬高未掩码探针）；以 `--domain-terms` 掩码后的异常片段排查为准 |

### 第 0 层卫生检测项详解（`--guide` / `--json`）
`11_verify.py` 在统计 4-gram 之前先执行第 0 层硬检，命中任意一项会在 `--guide` 中直接给出位置与改稿建议：
1. **乱码与异种字符检测**：拦截误混入的日文假名、韩文、奇怪拉丁碎片或解码异常符号；
2. **零频词拦截**：直接比对目标书 `index.json["零频词"]`，拦下原作者从不使用的词；
3. **低频错配搭配 + 高频平替建议**：命中原书低频/0 频搭配时，自动列出同概念下原书最高频的地道搭配供替换；
4. **语料拟合 AI 探针**：不靠拍脑袋写死，而是结合目标语料实际频次自动筛选「大模型高发但本书极罕见」的 AI 腔探针词；
5. **照抄例句粘贴检测**：比对 `例子.txt` / `纯文风包.md` 摘录，防止模型偷懒整句复制参考包例句（必须为 `0`）。

### 视点分桶（`--pov first|third|auto`）
第一人称作品与第三人称作品的句长、心理描写密度与代词频率存在显著差异。在 `11_verify.py` 中传入 `--pov`（或自动探测）可使门槛层与对照样本按一致视点分桶对标，避免用第一人称心理长段去误判第三人称动作场景。

## 2. 产物规模与覆盖率基准

| 检查项 | 目标区间 | 说明 |
|---|---|---|
| 单分片摘要字数 | 1,500 - 3,000 字 | 过短说明情节抽取得过于粗略；过长会超出下游二层归纳的上下文容量。 |
| 单卷纪要字数 | 1,800 - 3,500 字 | 确保收录卷内全部主干事件与伏笔闭环。 |
| 片尾特征词覆盖率 | 命中率 $> 25\%$ | `scripts/03_merge_notes.py` 自动化检测，用于防范长文本模型跳读。 |

## 3. 流水线常见问题排查

### 文本抽取阶段（Stage 0 · `00_extract.py`）

- **非正文文本混入（版权页 / 问卷 / 水印行）**：
  - *现象*：高频词表中出现排版制作、奥付、电子书声明、页眉或插图说明字符。
  - *排查*：确认 `drop_builtin_meta` 为 `true`（默认自动过滤常见版权/奥付/目次/后记页），并按需在 `config/project.json` 补充 `drop_headings`、`drop_file_patterns`、`drop_text_patterns` 或 `drop_line_patterns`。
- **EPUB 标题层级丢失**：
  - *现象*：抽取后正文缺失 `#`, `##` 等 Markdown 标题标记，后续切片无法定位章节。
  - *排查*：`00_extract.py` 已内置 **EPUB TOC（NCX / NAV）目录回退机制**，当正文 HTML 缺少标准 `h1-h6` 标签时会自动依据目录树补全标题；若仍缺失，检查 EPUB 内部 spine 与 TOC 锚点是否损坏。
- **字幕 / Galgame 剧本抽取噪声**：
  - *现象*：`.srt` / `.ass` 字幕或 Galgame 脚本混入时间轴、特效标签或引擎指令。
  - *排查*：直接将 `.srt` / `.ass` / 脚本文本路径填给 `source`，`00_extract.py` 会自动剥离时间轴与样式控制码并保留说话人对话结构；残留特有标记可通过 `drop_line_patterns` 清理。

### 语义分片阶段（Stage 1）

- **跨版块混合切片**：
  - *现象*：主线章节与番外外传被切入同一个 `chunk_NN.txt`，导致摘要视点割裂。
  - *排查*：确认外传等独立章节在 `_all.txt` 中是否使用了一级标题（`#`）。分片脚本默认禁止跨越一级标题切分。

### 脱敏与实体识别阶段（Stage 6 / 9）

- **单字人名误替换普通汉字**：
  - *现象*：角色名为单字（如「朋」「梓」「兰」）时，直接全局替换会破坏正常词汇。
  - *排查*：切勿将单字名直接放进粗暴字符串替换，应配置 `single_char_names` 走安全上下文脱敏；同时先运行 `python scripts/06b_suggest_entities.py` 自动扫描高频人名与专名，将地名/学校/组织填入 `anonymize_terms`。
- **「某甲/某乙」导致模型输出生硬**：
  - *排查*：在 `project.json` 中设置 `"anonymize_style": "names"`（或打包时传 `--anonymize-style names`），将脱敏代称切换为自然假名。

### 模型摘要与汇总阶段（Stage 2, 3, 5, 10）

- **模型跳读与截断漏读**：
  - *现象*：分片摘要中缺失后半截剧情；Stage 3 校验报错并给出片尾特征词未命中警告。
  - *排查*：降低 `chunk_chars` 参数重切更小分片，或使用 `--only` 单独对异常分片进行补跑。
- **原文摘录被二次润色**：
  - *现象*：摘要中「原文文风样本」包含非原作书写习惯的模型合成腔调。
  - *排查*：抽查几份 `work/notes/chunk_NN.md`，核对原句是否逐字一致；提示词需保持「严禁润色改写」约束。
- **剧情过度去重**：
  - *现象*：跨卷反复提及的同一历史事件在生成整书总结时被误删。
  - *排查*：清洗脚本仅去重同一卷内的完全重复段落，跨卷事件保留以维持各卷时间线独立完整性。

## 4. 文风统计的有效性边界

在分析与验收阶段，应明确各量化指标的技术边界：

1. **宏观边际统计对顺序免疫**：
   平均句长、对白占比、段长等宏观汇总指标仅衡量文本密度与体裁外壳。即使将一段文章的所有段落完全打乱，这些指标均不会发生变化（AUC = 0.500）。因此门槛层指标仅用于排除明显的格式偏差，不能直接判定文风是否符合原作。
2. **高频特征词 + 搭配关系是文风的双核心载体**：
   违和感既来自动词/方位词的非典型组合（`colloc.json` 0 次项），也来自脱离目标书常用词汇底色（`index.json["高频词"]`）。写前先看 `08_stylefit_query.py --top-words` 与 `--colloc`，比事后盲改省力得多。
3. **对照组必须做场景与视点切分**：
   全书整体平均值会平滑掉具体场景的写作特征（例如战斗段落均长显著短于日常与说教段落）。执行 `scripts/11_verify.py` 时建议传入 `--ref-pattern` 指定同类场景特征词，并配合 `--pov` 对齐叙述视点。
4. **新专有名词与跨题材词的干扰屏蔽**：
   新增角色名、地名或跨题材词汇会天然抬高未掩码的 0 频探针数值。同题材验收依赖内置专名等长平替；跨题材仿写则必须使用 `--cross-domain` 并通过 `--domain-terms` 显式声明新题材核心专词。
5. **改稿速度优化**：
   需要连续迭代 3 轮以上改稿验收时，先跑一次 `python scripts/11_verify.py --prewarm`（或在 `12_run_all.py` 加 `--prewarm-verify`）预热 4-gram 缓存，后续每次复检与 `--diff` 对比可在秒级完成。
